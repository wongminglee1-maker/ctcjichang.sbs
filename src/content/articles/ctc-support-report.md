在使用 CTC 金龙鱼（又称金龙鱼机场）的过程中，难免会遇到偶发的连接故障。然而，许多用户在向官方技术支持频道（如 Telegram 频道 `@ctcuser` 或服务工单）寻求帮助时，常常只发送一句“怎么连不上了？”、“节点全红了！”或者直接扔出一张毫无上下文的报错截图。

这类模糊的反馈不仅无法帮助客服工程师定位问题，反而会导致沟通成本成倍上升。很多技术新手经常询问：一份规范的 **机场测试报告怎么写**？截图前需要隐藏哪些敏感信息？本文将提供一套**专业的故障自检报告整理规范与去敏沟通模板**，让问题排查更加高效安全。

## 为什么一份规范的自检报告至关重要？

在大型分布式网络架构中，影响节点连通性的环节多达十余个：从用户本地路由、系统防火墙、本地宽带 DNS、中转入口 BGP、跨境专线传输，到境外落地服务器及协议握手校验。

通过提交一份包含关键环境参数的自检报告，可以瞬间帮助运维人员排除 90% 的无关变量：
- **精确的时间记录**：能让运维核对该时间段内是否存在中转入口 IP 更换或机房网络抖动；
- **清晰的网络环境标记**：能够明确是单点 ISP 问题还是通用全网故障；
- **准确的错误代码**：能直接区分是系统时间误差引起的 SS-2022 握手拒绝，还是 DNS 污染造成的解析黑洞。

## 提交反馈前必须严格执行的去敏安全清单

在向任何技术群组或工单系统发送截图与日志前，**必须执行以下去敏动作**，绝不能抱有侥幸心理：

### 1. 订阅 URL 与敏感 Token 遮挡
必须打码遮挡订阅链接中包含的「?token=...」或长串专属密钥，防止被恶意抓取盗刷。

### 2. 本机真实 IP 与网络接口隐私
切勿直接暴露本机的公网 IPv4/IPv6 地址与物理网卡 MAC 地址，保护个人物理位置隐私。

### 3. 个人账户与财务订单去敏
隐藏个人登录邮箱、注册账号以及充值订单流水号等个人敏感标识。

> **安全警示**：服务商官方客服绝不会以任何理由要求你提供明文密码或未经打码的完整订阅秘钥。任何要求私信索取账号凭据的均为仿冒诈骗。

## 标准化故障沟通模板（直接复制使用）

建议在提交工单或在技术群组交流时，复制并填写以下结构化文本：

```text
【CTC 连接问题排查反馈】
- 发生时间：2026年__月__日 __:__ (持续约 __ 分钟)
- 操作系统版本：[例: Windows 11 23H2 / iOS 18.1 / ColorOS 15]
- 客户端软件与版本：[例: Clash Verge Rev v1.7.5 / Shadowrocket v2.2.62]
- 物理网络环境：[例: 广东电信 1000M 家庭宽带 / 移动 5G 手机热点 / 某高校校园网]
- 本地基础网络：[已测 / 未测] (直连模式下国内网页能否正常打开: 是/否)
- 核心报错特征：[例: 节点测试全量超时 / 握手成功但浏览器无法加载网页 / 仅切换网络时掉线]
- 关键日志摘要 (已去敏)：
  [例: Handshake timeout / EOF / cipher authentication failed]
- 已执行过的自检排查：
  1. 已核实系统时间与北京时间误差在 10 秒以内
  2. 已更新至最新订阅链接
  3. 已配置腾讯公共 DOH 防污染
- 需要协助的问题：请协助核实该地区入口节点当前解析是否正常，感谢！
```

## 常见错误提示的自检含义速查表

根据客户端运行日志，可以快速对照排查：

| 日志关键字 | 底层技术原因 | 推荐优先自检动作 |
| :--- | :--- | :--- |
| `cipher not supported` | 客户端不支持 SS-2022 协议加密套件 | 升级客户端内核至最新稳定版本 |
| `handshake timeout` | 网络包在传输中被拦截，或系统时差超标 | 校准设备系统时间，配置加密 DOH 避开污染 |
| `connection refused` | 本地代理监听端口被关闭或抢占 | 检查是否有残留冲突代理软件，重启客户端 |
| `DNS lookup failed` | 节点域名无法通过本地 DNS 解析 | 将本地 DNS 更改为公共加密 DOH 地址 |

## 反馈后如何科学验证问题是否解决？

技术人员回复或更新维护后，请按照以下闭环逻辑验证：
1. **完全退出并重启客户端**，不要停留在原有的假死会话中。
2. **在配置管理中点击“更新订阅”**，强制拉取最新的专线入口 IP 解析。
3. **选择单个主力节点进行单点测试**，不要短时间内频繁并发全测所有节点，以免触发高频流量保护。
4. 若连接恢复，请在工单中简要回复“已恢复，谢谢”，便于技术人员关闭跟踪状态。
