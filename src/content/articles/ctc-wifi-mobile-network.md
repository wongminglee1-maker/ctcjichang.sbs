在日常使用 CTC 金龙鱼（又称金龙鱼机场）的过程中，很多用户经常发问：**机场频繁断线怎么办**？特别是手机在家庭 Wi-Fi 下能顺畅访问节点，但切到 5G/4G 手机流量，或回到办公室 Wi-Fi 时，客户端瞬间出现节点超时、握手停滞甚至整个网络无法刷新。面对此类问题，用户往往误以为是节点故障，反复重装客户端或重置订阅，结果反而引入更多未知的配置冲突。

本文针对**Wi-Fi 与手机移动数据网络的环境差异**，梳理网络切换时协议栈底层的状态迁移机制，并提供清晰、可执行的连通性自检方案。

---

## 为什么不同网络环境的表现截然不同？

手机流量与家庭宽带并非只是“计费方式不同”，它们在网络拓扑、传输层协议支持及运营商路由策略上存在根本差异：

| 评估维度 | 家庭宽带 Wi-Fi (电信/联通/移动) | 移动蜂窝数据 (5G / 4G) |
| :--- | :--- | :--- |
| **NAT 类型** | 通常为 Cone NAT 或 NAT3，依赖家用路由器分发内网 IP | 通常为对称型 NAT（Symmetric NAT），公网映射端口频繁变动 |
| **IPv6 支持** | 依据光猫及路由器拨号配置，部分局域网存在双栈延迟 | 运营商基站默认分配原生 IPv6 / IPv4 双栈地址 |
| **DNS 解析链路** | 经由本地路由器转发至本地 ISP 递归 DNS，易遭局域网拦截 | 经由蜂窝核心网直接解析，部分运营商省份存在私网 DNS 劫持 |
| **连接迁移能力** | IP 地址在局域网内相对静态 | 基站切换或小区重选时，设备出口公网 IP 会发生动态瞬断 |

当客户端建立基于 Shadowsocks-2022 的加密连接时，底层依赖持久化的 TCP/UDP 套接字（Socket）。一旦底层物理通道由 Wi-Fi 突变为蜂窝数据，操作系统的默认网络接口索引改变，原有套接字瞬间失效。若客户端未能及时感知接口变更并完成重连重握手，就会表现为“假死状态”。

## 本地网络正常状态的三步验证法

在怀疑节点不可用之前，必须先建立清晰的基准参照系，排查本地网络本身是否健康：

1. **彻底关闭代理客户端**：在系统设置中暂停代理，通过移动浏览器访问国内主流网站。如果直连模式下网页都加载缓慢或报错，说明本地 Wi-Fi 欠费、信号过弱或蜂窝基站正在拥塞，应优先恢复物理网络连接。
2. **测试局域网网关响应**：在家庭 Wi-Fi 环境下，尝试登录路由器管理后台（例如 `192.168.1.1`）。若内网网关响应延迟高达数百毫秒，说明 Wi-Fi 受到同频段信道干扰或路由器负载过载。
3. **核查蜂窝数据独立连通性**：关闭手机 Wi-Fi 开关，开启飞行模式 5 秒后关闭，强制基站重新完成附着，确认状态栏显示完整的 5G/4G 信号标识并能正常接收社交通讯推送。

## 网络切换后的四项标准检查清单

当网络发生切换且节点无法连通时，请按照以下逻辑顺序逐步执行排查：

```
[网络切换触发] 
   │
   ├─► 步骤一：查看客户端日志是否报 Socket Closed 或 Broken Pipe
   │      └─ 动作：手动点击客户端开关，完成一次断开与重新连接
   │
   ├─► 步骤二：核实系统时间误差（SS-2022 核心要求）
   │      └─ 动作：进入手机设置，确认「自动设置时间」保持开启
   │
   ├─► 步骤三：检查 IPv6 分流策略
   │      └─ 动作：在客户端中勾选「阻止 IPv6」或「优先使用 IPv4」
   │
   └─► 步骤四：刷新 DNS 缓存并验证 DOH
          └─ 动作：启用腾讯 DOH（https://doh.pub/dns-query）
```

### 1. 触发手动套接字刷新
网络接口变更时，操作系统的系统广播可能未能及时激活后台处于省电态的代理守护进程。最简单的恢复手段是：打开客户端主界面，手动关闭连接按钮，等待 2 秒后再重新点亮连接，强制客户端销毁旧套接字并绑定新网卡的 IP 地址。

### 2. IPv4 与 IPv6 的双栈冲突排查
很多移动 5G 网络分配了纯正的 IPv6 地址，若 CTC 订阅配置文件中的中转入口仅提供 IPv4 解析，而客户端本地优先尝试 IPv6 握手，就会发生长达数十秒的黑洞超时。**解决方案**：进入客户端高级设置，将路由解析策略调整为“IPv4 优先”或勾选“禁用 IPv6 流量泄漏防护”，使所有节点域名解析强制收敛至 IPv4 路由。

### 3. DNS 劫持与加密 DOH 防护
当连接切换到不同网络时，手机获取的本地递归 DNS 服务器也会随之改变。部分地方宽带或移动基站可能会对特定节点的域名发起 DNS 污染，将其解析至不存在的保留 IP。**建议做法**：在客户端配置的 DNS 模块中，配置公共安全 DNS，例如腾讯加密 DOH（https://doh.pub/dns-query），避免因运营商 DNS 篡改而导致无法找到专线入口。

## 如何正确记录故障现象与避免乱改配置

在网络排错过程中，最忌讳的是同时修改分流规则、删除订阅、开关系统全局代理并胡乱修改端口。这种无序操作会导致无法定位真实原因。

建议采取科学的排查记录习惯：
- **每次只改变一个变量**：例如只切换 DNS 配置，测试后记录结果；若无效立即改回默认值，再排查下一个项目。
- **记录网络环境与运营商**：明确标注“电信千兆 Wi-Fi 正常，移动 5G 握手失败”。
- **利用自动化报告工具**：可以通过本站的 [交互式网络自检中心](/diagnostics/)，在手机端一键生成去敏的诊断记录。如果需要向技术支持或社群寻求协助，可参考 [CTC 故障沟通与工单模板](/guides/ctc-support-report/)，在保护个人隐私的前提下准确表达故障现象。

关于更多操作系统层面的配置，如需排查电脑端网络冲突，请参阅 [Windows 11 代理与 TUN 模式详解](/guides/ctc-windows-proxy/)，或核对 [安卓系统后台保活设置指南](/guides/ctc-android-background/)。
