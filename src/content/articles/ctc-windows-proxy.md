在 Windows 11 操作系统中使用 CTC 金龙鱼（金龙鱼机场）的 Shadowsocks-2022 节点时，很多初学者常常困惑：**系统代理是什么意思**？为什么浏览器可以打开网页，但命令行终端中的 Git 无法拉取代码；或者关闭代理软件之后，电脑突然彻底无法上网，连国内网站也打不开；又或者同时安装了多个网络辅助工具后，端口频繁报错。

这些问题的根源并非 CTC 节点本身发生异常，而是用户对 Windows 网络流量接管层级理解不足。本文将剖析**系统代理、浏览器独立代理与 TUN 虚拟网卡模式**的核心差异，并提供 Windows 11 下的标准自检流程。

---

## 三种代理接管模式的技术机制对比

Windows 系统对网络请求的分流处理存在明确的调用栈层级。下表清晰展示了三种模式的工作边界：

| 模式名称 | 作用层级 | 典型接管流量 | 局限性与典型表现 |
| :--- | :--- | :--- | :--- |
| **系统代理 (System Proxy)** | 应用层 / 注册表环境 | 遵循 Windows 代理规范的浏览器及部分桌面办公软件 | 无法接管命令行终端（Git/SSH）、原生游戏 UDP 包及非标准端口应用 |
| **浏览器独立代理** | 浏览器沙箱层 (如 SwitchyOmega) | 仅针对特定浏览器的 HTTP/HTTPS 网页请求 | 优先级高于系统代理，容易覆盖客户端本地配置造成回环死锁 |
| **TUN 虚拟网卡模式** | 网络层 (OSI 第三层虚拟适配器) | 接管整机所有 TCP、UDP 及 DNS 流量 | 需要系统管理员权限安装驱动，路由规则配置不当可能影响内网打印机 |

```
[应用程序网络请求]
       │
       ├─► 浏览器 (独立插件扩展) ──────► 指定本地 HTTP 端口 (例: 127.0.0.1:7890)
       │
       ├─► 普通应用 (遵循系统设置) ────► 检查 Windows 注册表代理键值 ──► 客户端核心
       │
       └─► 命令行 / 游戏 / UDP 协议 ──► 绕过普通代理 ──► 直达物理网卡 (导致分流失败)
                                              ▲
                                              │ (若启用 TUN 虚拟网卡)
                                              └─► 被 Wintun/TUN 驱动完整捕获接管
```

## 为什么同时使用多个代理工具会引发冲突？

许多用户电脑中同时存在旧版原版客户端、新版 Clash Verge Rev、甚至其他本地开发辅助抓包工具。这些工具在后台运行时，争夺的是同一批系统资源：
1. **本地监听端口争抢**：客户端默认喜欢占用 `7890`（混合端口）或 `10808`（Socks5 端口）。若前一个工具未彻底退出，后一个工具启动时便会因“Bind Port Failed”而报错崩溃。
2. **注册表代理键值反复覆写**：Windows 系统代理实际上由注册表中的 `ProxyServer` 与 `ProxyEnable` 键值控制。多个软件并发修改该键值时，将导致系统路由指向无效端口。
3. **Wintun 驱动设备锁死**：TUN 模式依赖系统内核驱动，若多个内核同时尝试向路由表注入 `0.0.0.0/0` 默认网关，会导致操作系统网络栈瞬间瘫痪。

## Windows 11 网络与代理设置自检四步法

如果在日常使用中出现连通性异常，请依次按照以下步骤核查：

### 第一步：排查 Windows 11 系统代理注册表
按下快捷键 `Win + I` 打开系统设置，进入 **网络和 Internet > 代理**：
- 查看“使用安装程序脚本”是否被意外开启（通常应保持关闭）。
- 查看“手动设置代理”是否开启。若客户端正在运行，检查其代理 IP 是否为 `127.0.0.1`，端口是否与客户端内设置的端口完全一致。

### 第二步：客户端连接后的连通性测试
打开客户端，切勿直接打开外网测试，而应先执行基准验证：
- 在客户端节点列表中，找到香港或日本的 CTC 专线节点，点击延迟测试按钮。
- **特别提示**：由于 CTC 采用 Shadowsocks-2022 规范，系统时间偏差必须小于 30 秒。按下 `Win + I` > **时间和语言 > 日期和时间**，点击“立即同步”。

### 第三步：解决“关闭代理后无法上网”的典型故障
这是 Windows 用户最高频的求助问题：由于代理软件异常闪退或直接关机，未能正常调用 API 清理系统注册表，导致 Windows 依然固执地将所有流量发送给已经不存在的本地代理端口。

**恢复方法**：
1. 按下 `Win + R` 键，输入 `inetcpl.cpl` 并回车，打开“Internet 属性”。
2. 切换至“连接”选项卡，点击右下方的“局域网设置 (LAN Settings)”。
3. 取消勾选“为 LAN 使用代理服务器”复选框，勾选“自动检测设置”，点击确定保存。网络即刻恢复直连通信。

### 第四步：启用 TUN 模式解决终端与游戏分流
若你需要使用 Git 命令行、Docker 或玩外服游戏，纯粹的系统代理无法提供支持。此时应在客户端中开启 **TUN 模式**：
- 确认以**管理员身份**运行客户端软件。
- 在通用设置中安装 Service Mode（服务模式）或 TUN 内核驱动（如 Wintun）。
- 开启 TUN 开关后，在命令提示符中输入 `curl -I https://www.google.com` 即可直接验证终端是否已通过专线代理。

## 常见错误操作与避坑总结

在配置 CTC 客户端时，应避免以下误区：
- **误区一**：认为开启 TUN 模式就不需要分流规则。TUN 仅负责捕获底层数据包，数据包最终走直连还是专线，依然取决于规则列表。
- **误区二**：浏览器同时开启 SwitchyOmega 和客户端系统代理，导致 DNS 解析死锁。使用客户端时，建议将浏览器插件设为“使用系统代理”。
- **误区三**：以为延迟显示“超时”就是节点失效。先通过 [CTC 移动与家庭网络检查指南](/guides/ctc-wifi-mobile-network/) 排查本地宽带阻断，或使用本站的 [网络环境交互自检中心](/diagnostics/) 快速生成去敏自检报告。若需进一步咨询资费与套餐，请前往 [套餐核验中心](/pricing/)。
